# StudyFlow V0 数据模型设计

## 1. 设计约定

- 数据库：MySQL 8；字符集使用 `utf8mb4`；时间统一存储为 UTC 的 `DATETIME(3)`，接口以 ISO 8601 表示并带时区。
- 主键使用 `BIGINT`；所有业务表包含 `created_at`、`updated_at`。表名采用复数蛇形命名。
- 所有用户数据均带 `user_id`，即使 V0 只有一个账号；这保证后续扩展不会破坏隔离边界。
- 逻辑状态采用字符串枚举；重要变更不依赖物理删除的表保留记录。学习任务在 V0 可物理删除。
- ICS 原文件先存为本地受控文件，其路径和摘要保存在数据库；不要把二进制文件直接放进表中。

## 2. 实体关系

```text
users 1 ── * import_jobs 1 ── 1 source_files
                 │
                 └── * schedule_drafts ── 0..1 schedules

users 1 ── * schedules
users 1 ── * study_tasks
```

## 3. 表设计

### 3.1 `users`：本地账号

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | 主键 |
| username | VARCHAR(64) | 非空、唯一；登录名 |
| password_hash | VARCHAR(100) | 非空；BCrypt 哈希 |
| enabled | TINYINT(1) | 非空，默认 `1` |
| created_at / updated_at | DATETIME(3) | 非空 |

### 3.2 `source_files`：导入源文件元数据

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | 主键 |
| storage_path | VARCHAR(512) | 非空、唯一；受控存储相对路径 |
| original_filename | VARCHAR(255) | 非空 |
| content_type | VARCHAR(100) | 非空，例如 `text/calendar` |
| size_bytes | BIGINT | 非空；最大 10 MB |
| sha256 | CHAR(64) | 非空；内容摘要，建立索引 |
| created_at / updated_at | DATETIME(3) | 非空 |

### 3.3 `import_jobs`：一次导入任务

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | 主键 |
| user_id | BIGINT | 非空，外键至 `users.id` |
| source_file_id | BIGINT | 非空，唯一，外键至 `source_files.id` |
| import_type | VARCHAR(20) | 非空；V0 固定为 `ICS` |
| status | VARCHAR(20) | 非空；`PENDING` / `PARSING` / `SUCCEEDED` / `FAILED` |
| total_count | INT | 非空，默认 `0` |
| success_count | INT | 非空，默认 `0` |
| failure_reason | VARCHAR(1000) | 可空；仅保存对用户可展示的概要原因 |
| started_at / finished_at | DATETIME(3) | 可空 |
| created_at / updated_at | DATETIME(3) | 非空 |

索引：`idx_import_jobs_user_created (user_id, created_at DESC)`。

### 3.4 `schedule_drafts`：待确认的日程草稿

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | 主键 |
| import_job_id | BIGINT | 非空，外键至 `import_jobs.id` |
| user_id | BIGINT | 非空，外键至 `users.id` |
| title | VARCHAR(255) | 非空 |
| start_at / end_at | DATETIME(3) | 非空，`end_at > start_at` |
| timezone | VARCHAR(64) | 非空；原始时区，如 `Asia/Shanghai` |
| location | VARCHAR(255) | 可空 |
| description | TEXT | 可空 |
| recurrence_rule | VARCHAR(512) | 可空；规范化 RRULE，V0 仅接受每周规则 |
| recurrence_until | DATETIME(3) | 可空 |
| excluded_dates | JSON | 可空；UTC 日期时间数组 |
| original_payload | JSON | 非空；保留解析字段和原始 VEVENT 片段 |
| validation_errors | JSON | 可空；字段级错误数组 |
| duplicate_of_schedule_id | BIGINT | 可空；疑似重复的正式日程 |
| status | VARCHAR(20) | 非空；`PENDING` / `CONFIRMED` / `REJECTED` |
| confirmed_schedule_id | BIGINT | 可空、唯一；确认后指向 `schedules.id` |
| confirmed_at | DATETIME(3) | 可空 |
| version | INT | 非空，默认 `0`；乐观锁 |
| created_at / updated_at | DATETIME(3) | 非空 |

索引：`idx_schedule_drafts_import_status (import_job_id, status)`、`idx_schedule_drafts_user_status (user_id, status)`。

### 3.5 `schedules`：已确认的正式日程

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | 主键 |
| user_id | BIGINT | 非空，外键至 `users.id` |
| source_draft_id | BIGINT | 可空、唯一；外键至 `schedule_drafts.id` |
| title | VARCHAR(255) | 非空 |
| start_at / end_at | DATETIME(3) | 非空，`end_at > start_at` |
| timezone | VARCHAR(64) | 非空 |
| location | VARCHAR(255) | 可空 |
| description | TEXT | 可空 |
| recurrence_rule | VARCHAR(512) | 可空 |
| recurrence_until | DATETIME(3) | 可空 |
| excluded_dates | JSON | 可空 |
| fingerprint | CHAR(64) | 非空；标题、时间、地点、规则规范化后的 SHA-256 |
| created_at / updated_at | DATETIME(3) | 非空 |

唯一约束：`uk_schedules_user_fingerprint (user_id, fingerprint)`，用于防止重复确认和重复导入。

索引：`idx_schedules_user_start (user_id, start_at)`。

### 3.6 `study_tasks`：学习任务

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | 主键 |
| user_id | BIGINT | 非空，外键至 `users.id` |
| title | VARCHAR(255) | 非空 |
| description | TEXT | 可空 |
| due_at | DATETIME(3) | 可空 |
| estimated_minutes | INT | 可空；填写时为 1–1,440 |
| priority | VARCHAR(10) | 非空，默认 `MEDIUM`；`LOW` / `MEDIUM` / `HIGH` |
| status | VARCHAR(20) | 非空，默认 `TODO`；`TODO` / `DONE` |
| completed_at | DATETIME(3) | 可空；状态为 `DONE` 时非空 |
| created_at / updated_at | DATETIME(3) | 非空 |

索引：`idx_study_tasks_user_status_due (user_id, status, due_at)`。

## 4. 状态流转与关键约束

```text
import_jobs:     PENDING → PARSING → SUCCEEDED
                              └────→ FAILED

schedule_drafts: PENDING → CONFIRMED
                       └──→ REJECTED

study_tasks:     TODO → DONE
```

- `PARSING` 到 `SUCCEEDED` 的同一事务中，写入草稿及统计数量；失败仅更新任务状态与原因。
- 确认草稿时，使用草稿 `version` 乐观锁，并在同一事务内创建 `schedules` 记录、更新草稿状态和 `confirmed_schedule_id`。
- `uk_schedules_user_fingerprint` 是最后一道幂等防线；出现唯一键冲突时将草稿标为重复并提示用户，而非创建第二条日程。
- 查询重复日程时不预先将无限重复规则展开存库，而是在查询区间内计算发生实例。
